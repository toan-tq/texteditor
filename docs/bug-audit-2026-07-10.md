# Bug Audit — 2026-07-10

Kết quả rà soát toàn bộ codebase (22 file Swift, ~5.800 dòng) sau khi điều tra
bug "panel kết quả search không đóng được". Tài liệu này ghi lại: nguyên nhân
gốc từng bug, cách fix đã áp dụng, và các vấn đề đã biết nhưng **chưa** fix.

## Đã fix

### 0. Panel kết quả Find in Files không có cách nào đóng (bug gốc do user báo)

**Triệu chứng:** Sau khi mở dialog Find in Files rồi đóng đi, thi thoảng một
panel hiện ở đáy cửa sổ (các cột File / Line / Content) và không có cách nào
đóng được.

**Nguyên nhân gốc (2 lỗi cộng hưởng):**
1. `findAllButton.keyEquivalent = "\r"` biến Find All thành default button của
   *cả cửa sổ* — nhấn Enter ở **bất kỳ field nào** trong dialog đều kích hoạt
   search. Vì ô Find được tự điền từ text đang bôi đen và ô Folder tự điền từ
   file hiện tại, search chạy "ngầm" sau floating panel mà user không nhận ra.
   Panel kết quả mở ra ở đáy main window, bị dialog che mất; đóng dialog xong
   mới thấy.
2. `hideDirResults()` tồn tại nhưng **không có bất kỳ call site nào**: panel
   không có nút Close, không có menu item, và handler phím Escape trong
   `DirSearchResultsView.keyDown` là stub rỗng (chỉ có comment
   `// Hide results -- notify parent`).

**Fix:**
- `Views/DirSearchResultsView.swift`: thêm nút **Close** vào status row (cạnh
  nút Stop), thêm callback `onCloseRequested`, phím **Escape** giờ gọi callback
  này thật.
- `Views/EditorTabViewController.swift` (`loadView`): nối
  `onCloseRequested` → set cờ hủy search đang chạy + `hideDirResults()`.
- Bug Enter được fix riêng ở mục #6 bên dưới.

### 1. "Replace All" trong Find/Replace in Files không thay thế gì cả

**File:** `Views/EditorTabViewController.swift` (extension `FindInFilesDelegate`)

**Nguyên nhân:** Delegate `findInFiles(_:searchFor:replaceWith:...)` nhận tham
số `replacement` nhưng thân hàm **không bao giờ dùng nó** — toàn bộ hàm chỉ
search. User bấm "Replace All" tưởng đã thay xong nhưng file trên đĩa không đổi.

**Fix:**
- Khi `replacement != nil`:
  - Hiện **dialog xác nhận** trước (thao tác ghi đè file trên đĩa, không undo
    được).
  - Mỗi file được đọc qua `FileService.readFile` (chuẩn hóa LF + nhận diện
    line ending gốc), thay thế theo từng dòng rồi ghi lại qua
    `FileService.saveFile` với **line ending gốc** (file CRLF giữ nguyên CRLF).
  - Helper mới `replaceOccurrences(in:needle:replacement:regex:matchCase:wholeWord:)`:
    - Regex mode: collect match trước, splice **ngược từ cuối lên** để offset
      không bị lệch; template `$1, $2...` resolve qua
      `regex.replacementString(for:in:offset:template:)`.
    - Literal mode: tìm bằng `range(of:options:.caseInsensitive)` trên **chuỗi
      gốc** (không dùng bản lowercased — tránh lệch offset với ký tự đổi độ
      dài khi case-fold như `İ`).
    - Cả hai mode đều tôn trọng Match Case / Whole Word.
  - File đang mở trong tab **có sửa đổi chưa save** → **bỏ qua** (không ghi đè
    công sức của user), báo số lượng skip trong status.
  - File đang mở trong tab sạch → tự **reload** sau khi replace xong.
  - Giới hạn 5000 match chỉ áp dụng cho search; replace **không cap** (cap sẽ
    khiến file bị thay thế nửa chừng một cách âm thầm).
- Status hiển thị: `Replaced N matches in M files (K files skipped: unsaved changes)`.

### 2. Crash backup có thể restore sai nội dung vào sai file (nguy cơ hỏng dữ liệu)

**File:** `Services/CrashRecoveryService.swift`

**Nguyên nhân:** File backup đặt tên theo **vị trí trong danh sách tab dirty**
(`0.bak`, `1.bak`...), nhưng logic skip-ghi-nếu-hash-không-đổi lại key theo
**identity của document**. Kịch bản lỗi:

1. Tab A và B đều dirty → `0.bak` = A, `1.bak` = B.
2. User save A → A sạch.
3. Chu kỳ backup sau: danh sách dirty = [B], B giờ ở slot 0. Hash của B không
   đổi → **không ghi đè `0.bak`** (vẫn chứa nội dung của A). `index.txt` ghi
   đường dẫn của B ở dòng 0. `1.bak` bị xóa (orphan cleanup).
4. Crash → restore đọc `index.txt`: đường dẫn B ↔ nội dung `0.bak` (của A!).
   User bấm save là ghi nội dung file A đè lên file B.

**Fix:** `backupHashes: [ObjectIdentifier: Int]` đổi thành
`backupStates: [ObjectIdentifier: (hash: Int, index: Int)]`. Điều kiện ghi:
`hash đổi HOẶC slot index đổi`. Tab đổi vị trí slot sẽ được ghi lại dù nội
dung không đổi, đảm bảo `<i>.bak` luôn khớp với dòng thứ `i` của `index.txt`.

### 3. Menu "Open Recent → Clear Menu" bị vô hiệu vĩnh viễn

**File:** `App/MainMenu.swift` (`RecentMenuDelegate.menuNeedsUpdate`)

**Nguyên nhân:** Item được add với action `clearRecentFiles(_:)` nhưng không
set `target`. Selector này nằm trên `RecentMenuDelegate` — không thuộc
responder chain — nên macOS auto-disable item (luôn xám, bấm không được).

**Fix:** Gán `clearItem.target = self` (giống item `openRecentFile` đã làm đúng).

### 4. Recent files đã clear lại "hồi sinh" sau khi mở file mới

**File:** `Services/PersistenceService.swift`, `Views/EditorTabViewController.swift`

**Nguyên nhân:** `EditorTabViewController` giữ một bản copy `recentFiles` trong
RAM, load một lần lúc khởi tạo và không bao giờ đồng bộ lại. "Clear Menu" xóa
file trên đĩa nhưng không đụng tới bản RAM; lần mở file kế tiếp,
`addRecentFile(_:to:)` insert vào mảng cũ rồi save → toàn bộ lịch sử cũ quay lại.

**Fix:** Bỏ hẳn property cache `recentFiles`; `PersistenceService.addRecentFile(_:)`
giờ theo mô hình **load–modify–save** trực tiếp trên đĩa (danh sách tối đa 10
phần tử, không cần cache). Cả 3 call site được cập nhật.

### 5. Đóng Find panel bằng nút ✕ đỏ để lại highlight vàng vĩnh viễn

**File:** `Views/FindPanelController.swift`, `Views/EditorTabViewController.swift`

**Nguyên nhân (2 đường):**
1. Panel có style `.closable`; bấm ✕ trên title bar đóng cửa sổ **không qua**
   `closeClicked()` → `findPanelDidClose` không được gọi → temporary
   background highlight (màu vàng) trong editor không bao giờ được xóa.
2. Hai debounce có thể fire **sau khi** panel đã đóng và re-apply highlight:
   - `searchDebounce` (200ms, gõ trong ô Find của panel),
   - `findUpdateWorkItem` (300ms, gõ trong editor khi panel đang mở).

**Fix:**
- `FindPanelController` conform `NSWindowDelegate`, set `panel.delegate = self`;
  `windowWillClose` và `closeClicked` cùng gọi chung `cleanupOnClose()`
  (cancel `searchDebounce` + notify `findPanelDidClose`).
- `EditorTabViewController.findPanelDidClose` cancel `findUpdateWorkItem`
  trước khi clear highlight.

### 6. Enter trong dialog Find in Files vô tình chạy search

**File:** `Views/FindInFilesController.swift`

**Nguyên nhân:** `findAllButton.keyEquivalent = "\r"` — default button cấp
cửa sổ, nên Enter ở folder combo / file types / exclude đều chạy Find All
(nguồn gốc của bug #0).

**Fix:** Bỏ keyEquivalent; `findField.delegate = self` và xử lý Enter qua
`control(_:textView:doCommandBy:)` — **chỉ** Enter trong ô Find mới chạy
search, Enter ở field khác không làm gì.

### 7. Kéo-thả tab bị lệch 42px

**File:** `Views/TabBarView.swift` (`mouseDragged`)

**Nguyên nhân:** Target index tính bằng `Int(point.x / tabWidth())` nhưng tab
đầu tiên bắt đầu tại `tabBarLeftMargin` (42pt) — mọi ranh giới swap bị dịch
sớm ~1/3 chiều rộng tab, reorder có cảm giác "nhảy".

**Fix:** `Int((point.x - tabBarLeftMargin) / tabWidth())` (vẫn clamp về
`0...tabs.count-1`).

## Đã biết nhưng CHƯA fix (độ ưu tiên thấp)

### 8. Whole-word check trong dir **search** sai với ký tự Unicode đổi độ dài khi lowercase
`EditorTabViewController.swift`, nhánh search literal: range tìm trên chuỗi
`lowercased()` được áp lên chuỗi gốc để check whole-word. Ký tự như `İ`
(U+0130) lowercase thành 2 code unit → lệch offset.
*Đường replace đã dùng cách đúng (`range(of:options:.caseInsensitive)` trên
chuỗi gốc) — có thể áp dụng tương tự cho search.*

### 9. Đổi encoding âm thầm khi save
`FileService.swift`: file mở bằng fallback ISO-8859-1 luôn được save lại thành
UTF-8; UTF-8 BOM bị strip lúc đọc và không khôi phục lúc save.
*Đề xuất: lưu encoding/BOM phát hiện được vào `TabDocument` (như đã làm với
`lineEnding`) và dùng lại khi save.*

### 10. Font panel: đổi font family không có tác dụng với file có syntax highlight
`SyntaxHighlighter.highlightRange` luôn áp lại `AppTheme.monoFont` (hardcode
Menlo) trên vùng highlight → chọn family khác bị revert ngay lần highlight kế
tiếp; chỉ size (qua `AppTheme.fontSize`) có tác dụng.
*Đề xuất: `AppTheme` lưu cả font name, các biến thể bold/italic derive từ đó.*

### 11. Gutter số dòng không giãn khi đổi font size
`LineNumberRulerView.updateThickness` chỉ tính lại khi **số chữ số** của tổng
dòng thay đổi (`digits != lastDigitCount`), không phản ứng khi font size đổi.
*Đề xuất: đưa font size vào điều kiện so sánh.*

### 12. `pendingDirtyRange` union các range thuộc hệ tọa độ khác nhau
`SyntaxHighlighter.swift`: các edit liên tiếp trong cùng runloop tick được
union mà không dịch range cũ theo delta của edit mới. Đã có clamp nên không
crash; hậu quả tối đa là highlight sót/thừa một vùng thoáng qua.
*Đề xuất: dịch `pendingDirtyRange` theo delta trước khi union.*
